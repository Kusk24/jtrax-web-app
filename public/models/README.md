# Chess models

Two models the academy trained, served to the browser with onnxruntime-web
alongside the Stockfish worker in `public/stockfish/`.

| File | Size | What it is |
|---|---|---|
| `novice_int8.onnx` | 26 MB | 25.7M character-level GPT, trained from random weights. ~520 Elo. |
| `strong_fp16.onnx` | 47 MB | Maia-2 fine-tuned on 2000–2800 games. ~1300–1450 Elo. |
| `ort/` | ~40 MB | onnxruntime's WASM, copied from `node_modules`. |

**None of those are in git.** 73 MB of weights plus a dependency artefact would
sit in the history forever, so they are reproduced instead:

```bash
pnpm models:setup
```

That copies the WASM out of `node_modules` and the weights out of the
`jtrax-ai` checkout next door. Set `JTRAX_AI_DIR` if it lives elsewhere, or
regenerate the weights there:

```bash
conda activate jtrax-ai
python step9_export_novice_onnx.py     # novice  -> int8
python step10_export_strong_onnx.py    # strong  -> fp16
```

To serve them from object storage rather than this origin, set
`NEXT_PUBLIC_MODEL_BASE_URL`. Nothing in the app assumes they are local.

The small JSON files here **are** committed — `maia-moves.json` in particular,
because its order *is* the policy head's index space. It is generated by
`jtrax-ai/tools/export_web_assets.py`; regenerate rather than hand-edit.

Why the two models are quantised differently, and what was measured:
`jtrax-docs/features/training-our-own-chess-opponents.md`.
